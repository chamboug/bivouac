# Architecture

How Bivouac works today, part by part. The reasons are in the [decision log](decisions.md) (`Dxx`); procedures are in the [runbook](runbook.md); the brief ([`CLAUDE.md`](../CLAUDE.md)) has the rules and a one-line map. `example.org` and `203.0.113.10` stand in for the real domain and IP (D71).

## Host

- **Flatcar Container Linux**, official image, stable channel: immutable, automatic A/B updates with rollback, Docker included, no package manager. Everything runs in containers. No custom image (D7).
- **Ignition** (written as Butane, no secret) runs on first boot only: public SSH keys, sshd config (`PermitRootLogin no`, `PasswordAuthentication no`, `KbdInteractiveAuthentication no`, port 22), the metadata block (D62), the SSH key sync (D63), the reconciler unit and its fallback script (D61), static IPv6 (D67), 2 GiB of zram swap (D94). Anything that changes later comes from Git through the reconciler.
- **Updates**: `update_engine` downloads, `locksmithd` reboots in a night window (04:00 UTC). About a minute of downtime; containers use `restart: unless-stopped`; Pocket ID needs one or two more minutes (D68).
- **Hetzner**: no official Flatcar image, so a snapshot is made once with `hcloud-upload-image`, from an image checked on the Mac (D65). The server is created or reinstalled (`rebuild`) from it, with the Ignition JSON as user-data (32 KiB limit). Hetzner volumes are not mounted automatically; there is no root password.
- **Server**: a CX23 (x86, 2 vCPU, 4 GB) in `fsn1`, reinstalled in place (D24, D25). Primary IPv4 `203.0.113.10` and a Primary IPv6, both `auto_delete=false` and delete-protected. Assigning a Primary IP needs the server off, in the same location.
- **Costs** (verified, Nov. 2026): Primary IPv4 €0.50/month excl. VAT; CX23 €0.01056/hour incl. VAT; `cpx12` €0.02208/hour; a snapshot €0.0143/GB/month (0.55 GB for Flatcar).
- **Later, a mini PC at home**: Flatcar on the hardware with the same Ignition; Tailscale for admin access; never `*.ts.net` (passkeys would be bound to it).

## Host security

- **SSH**: keys only, user `core` (sudo and Docker; read-only by discipline, D11). Claude sessions in the cloud have no SSH access. One key per machine and per use; the only list is the instance's `ssh-keys.yml` (D12, D63). Rescue when every key is lost: runbook section 11.
- **Secrets on the server**: the age key and the deploy key are placed over SSH in `/etc/bivouac/` (mode 600), never in user-data, which any process on the server can read (D7). Containers cannot reach the metadata service (D62).
- **Hetzner Cloud firewall**, outside the machine: inbound 22/tcp, 80/tcp, 443/tcp and 443/udp, IPv4 and IPv6; Docker's iptables rules cannot bypass it. Emergency stop: close 80/tcp, 443/tcp and 443/udp there, IPv4 and IPv6 (D69); removing DNS records closes nothing.
- **No published port** except Caddy's. Two Docker networks with fixed subnets (D56): `bivouac` (apps, Caddy, Postgres, reconciler) and `bivouac-internal` (Pocket ID, Caddy, Postgres, reconciler, status page). Every container drops `NET_RAW` and runs with `no-new-privileges`. Apps are capped at 1 GiB, 512 processes and 20 Postgres sessions (D94).
- **The Docker socket** is mounted in the reconciler only (D8).
- **Least privilege**: one Postgres role per app; OVH keys limited to one zone (D49); tokens limited to the minimum (see "GitHub tokens").
- **Rate limits** on login: Pocket ID's own, which trusts only Caddy's address (D27); `local` apps' auth library.
- Not used: CrowdSec, fail2ban (keys only, and only Caddy exposed).

## Domains

- `*.apps.example.org` points to the Primary IPv4 (`A` only, no `AAAA`: D67): a new app needs no DNS change (D13).
- `auth.apps.example.org`: Pocket ID, **final** (D40). `gate.apps.example.org`: Tinyauth, not built. `status.apps.example.org`: the status page.
- Reserved app names: `auth`, `gate`, `status`, Postgres and platform names, `*-mcp` (D34).
- `example.org` and `www.example.org` point to the same IP, for a static page (D22, not built).
- An app may also have a custom domain in its manifest.
- Mail DNS: SPF exists for OVH (`v=spf1 include:mx.ovh.com ~all`) and must never be duplicated; `_dmarc` is `p=none` (D70).

## Network and access

- **Caddy**: automatic HTTPS, one certificate per name (`http-01`, no DNS plugin). The Caddyfile is generated by the reconciler (and by `bivy validate`, then checked with `caddy validate`); Caddy has no Docker socket (D53). HSTS and `nosniff` on every answer (D94).
- **Pocket ID's first-admin paths** are refused for good, except from `auth.setupFrom` during `bivy init` (D15).
- **Admin access**: SSH only. No admin interface exposed.

## Data

- **One shared Postgres 18** (`postgis/postgis:18-3.7`, pinned by digest), one database and one role per app, `REVOKE CONNECT … FROM PUBLIC`; extensions per manifest, from an allowlist (D51, D56). All apps share the major version; majors go through dump and restore, high risk (D29). pgvector needs our own image, the day an app needs it.
- **Files**: per-app Docker volumes declared in the manifest (`name → mount path`), backed up nightly. Apps use the storage module, on the volume or on S3 when `S3_BUCKET` is set (D72).
- **Migrations**: at startup, additive only; a destructive change takes two deployments (D21).

## Secrets

- **SOPS + age in the instance repo** (`secrets/platform.sops.yaml`, D57): master secret, Pocket ID's `ENCRYPTION_KEY` and `STATIC_API_KEY`, backup credentials and restic password, Pushover token and group key, healthchecks.io ping URLs, the mail password, the GHCR token, Hetzner and OVH tokens if kept there.
- **The age key** exists in three places: the server, the owner's password manager, the owner's Mac (`~/.config/sops/age/keys.txt`). Never in a repo or in GitHub Actions (D35).
- **Derived secrets** (D14): `HMAC(master secret, purpose)`; never stored, recomputed after a rebuild.
- **An app's own secrets** (D97): `secrets/apps/<app>.sops.yaml`, each name an environment variable of that app (runbook section 18).
- **Pocket ID's `ENCRYPTION_KEY`** encrypts its token signing keys; losing it loses them (what happens exactly is undocumented). With `_FILE`, a trailing newline would become part of the key.

## Backups

- **Nightly at 02:00 UTC** (D74): one `pg_dump` per database and every declared volume, sent with **restic** over S3 to **Backblaze B2, EU Central** (D16, D73). The reconciler runs restic in throwaway containers (D33). Retention: 7 daily, 4 weekly, 6 monthly (D75).
- **The server's B2 key cannot delete**; the bucket keeps hidden files 30 days; caps $0.10/day storage and $1/day downloads (D73).
- **B2 pricing** (verified, Nov. 2026): 10 GB free, then $6.95/TB/month; downloads free up to 3× the stored volume.
- `backup: { stop: true }` stops an app that keeps data in files during the backup (D20).
- **Weekly restore test**: `restic check` and the latest dumps loaded into a throwaway Postgres, reported to healthchecks.io (D75).
- **Restoring**: one app with `bivy restore <app>` / `restore-app` (D90, D101, runbook section 14); the whole platform with `bivy rebuild` (D91, sections 15 and 16).

## Authentication

- **Pocket ID** (v2.19.2): passkeys only, in the shared Postgres. Facts verified on that version:
  - sign-up tokens: at most 31 days, 1 to 100 uses, attached to groups;
  - per-client group restriction, groups in the ID token with the `groups` scope;
  - admin API with `STATIC_API_KEY`; a client's chosen secret set through `POST /api/oidc/clients/{id}/secrets`; `PUT` replaces the whole client (D52);
  - several passkeys per account (users are advised to have at least two, phone and computer, or one synced passkey); one-time **Login Code** links made by the admin for someone who lost theirs; no email code (D37);
  - the first admin is created at `/setup` by whoever gets there first (D15).
- **Mail for Pocket ID only**: an OVH mailbox through `smtp.mail.ovh.net:587`, STARTTLS, password as a file; settings from Git (`UI_CONFIG_DISABLED=true`). Hetzner blocks outbound 25 and 465. **Apps never get that password** (D70).
- **Auth modes** (D10), in the manifest:
  - `oidc` (default): the shared Nuxt layer speaks OIDC, encrypted-cookie session of 24 h (D79);
  - `forward` (*not built*): Caddy `forward_auth` to **Tinyauth** (v5.2.0 verified), connected to Pocket ID, `ACLS_POLICY=deny`, per-app groups through `TINYAUTH_APPS_<APP>_OAUTH_GROUPS`, Caddy overwriting `X-Forwarded-Host`, cookie on `.apps.example.org`. Before building it: D94's open item on apps reaching each other;
  - `public`: no protection;
  - `local`: the app signs its own users in with **Better Auth**; the platform gives `SESSION_SECRET` (D97). Pocket ID stays reserved for the invited community; a "Sign in with Pocket ID" button (generic OAuth) can sit beside local accounts. If several public sites ever had to share accounts, an IdP with passwords would be reconsidered.

## Deployment

- **Images** are built in each app repo's GitHub Actions and pushed to GHCR, private (D17). Nothing is built on the server.
- **A new version** (D5, D64, D86): after a green build, `propose.yml` opens a PR on the instance repo changing the image tag; `merge-deployments.yml` merges it when Validate is green and the shared layers did not change. Only repos meeting D92's conditions hold the token; elsewhere the owner changes the image by hand (D88, D98).
- **App manifest** (D19):
  ```yaml
  # apps/recettes.yml
  image: ghcr.io/<user>/recettes:sha-abc123
  name: recettes            # → recettes.apps.example.org
  port: 3000                # internal port, 3000 by default
  health: /api/health       # default; optional for third-party apps
  database: { extensions: [postgis] }   # optional
  auth: oidc                # oidc | forward | public | local
  groups: [famille]         # allowed Pocket ID groups
  volumes: { uploads: /app/uploads }    # name → mount path
  backup: { stop: false }   # true for SQLite, Node-RED, etc.
  env:                      # renaming of values provided by the platform
    GF_AUTH_GENERIC_OAUTH_CLIENT_ID: ${oidc.clientId}
  mcp: false                # true: Claude may connect to the app's /mcp (D85)
  ```
  The platform injects `DATABASE_URL`, `OIDC_ISSUER`, `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET`, `MCP_RESOURCE` (D85), `SESSION_SECRET` (`local`), and the app's own secrets. `SMTP_*` waits for a send-only relay (D70).
- **Static sites** (*not built*, D22): `sites/<name>/` and `sites/<name>.yml`, served by Caddy's `file_server`.
- **Renovate** (Mend's free plan, one run every 4 hours): in app repos, the shared layers only (D81). On the instance repo it is planned for third-party images (minors merged if green, majors as PRs, never a Postgres major, D29) but **not set up**: the template has no `renovate.json`, and base images are updated by Claude (D95).

## The reconciler

TypeScript on Node LTS (`packages/reconciler`), image `ghcr.io/chamboug/bivouac-reconciler:sha-<commit>@sha256:…` (D50, D61). It polls Git every minute with the read-only deploy key (D2); `POST /sync` triggers a pass now (D3). Each pass (D54, D55):

1. moves itself to the version named in `platform.yml` if it differs (D61);
2. validates the commit (an invalid one applies nothing);
3. writes the SSH key list (D63);
4. decrypts secrets;
5. base services: networks, Postgres, Pocket ID, Caddy;
6. per app: database, role, extensions; OIDC client (and MCP client, D85) through Pocket ID's API; container with the right image, health-checked;
7. regenerates the Caddyfile and reloads Caddy;
8. checks the metadata block, the disk, and sends alerts and the heartbeat.

It also runs the nightly backup, the weekly retention and restore test (D74, D75), `restore-app` (D90), `restore-platform` (D91), and the internal API for the status page (D96).

Properties: **idempotent** (the same code installs, updates and rebuilds); **never deletes data**; **monitored deployment**: a failing image is stopped and marked, not retried until the manifest changes (D21).

**Not built yet** (layer 6 and on demand): archiving on removal (D18), automatic rollback to the previous image (D21), static sites (D22), Tinyauth (D10), resource history (D42).

## GitHub tokens

Verified: GHCR accepts only classic PATs; on GitHub Free organization secrets do not reach private repos.

- **Classic `read:packages` PAT**, no expiry, in SOPS: the server pulls private images (D17).
- **Fine-grained `bivouac-deploy` PAT**, no expiry, instance repo only: in the owner's password manager, set by hand only on repos meeting D92 (D36).
- **Read-only deploy key**: generated on the server, added by the owner (D30, D66).
- **One-day fine-grained PAT** for `bivy rebuild --test` only (D91). `bivy init` needs none (D99).
- **Claude's `gh` tokens** on the owner's Mac (D78): read CI, open and comment on PRs; cannot push, merge or set secrets.
- Rotating any of them needs the owner's consent (rule 5).

## `bivy`, the CLI

TypeScript on Node LTS (`packages/bivy`), run with `npx` or as an image. It talks to official APIs directly and depends on neither `gh`, `hcloud` nor `sops` (D31); it asks for each credential itself and keeps it in `~/.config/bivouac/` (D93). Adapters behind written contracts: [`docs/adapters.md`](adapters.md).

| Command | What it does | State |
|---|---|---|
| `bivy validate` | The instance repo's checks (D48) | used by CI |
| `bivy ignition` | Compiles the Butane (D60) | built |
| `bivy ssh`, `bivy exec` | Reach the server or an app without knowing SSH | built |
| `bivy init` | Empty Hetzner project + domain → running platform (D99) | never run for real |
| `bivy configure backups\|alerts\|mail` | Adds a missing part (D99) | built |
| `bivy rebuild --test` | Temporary server restored from backups, checked, destroyed (D91) | proven |
| `bivy rebuild` | Same server or IPs, restored from backups (D91) | `--plan` only so far |
| `bivy restore <app>` | One app's data back to a nightly copy (D101) | `--plan` only so far |
| `bivy machine add` | Key for a new machine, by PR (D38) | not built |

## Admin interface

- **No interface edits config**: everything goes through Git.
- **Pocket ID's interface**: users, invitations, groups.
- **Status page** (D96): `status.apps.example.org`, groups from `platform.yml` (`status`); platform services and apps, versions, health, memory, restarts, latest logs (never Postgres's), last pass, latest backup, open incidents, host disk and memory; one action, "Sync now". Follows the brand in `docs/brand/` (D100).
- **App MCPs** (D85): `oidc` apps with `mcp: true` serve `/mcp`, signed in through Pocket ID.

## Alerts

Pushover, every message at normal priority (D45, D82). The server reports failed deployments, disk above 80%, failed backup or restore test, secrets that fail to decrypt, a refused SSH key list, and the quarterly rebuild-test reminder; one message per change of state, one reminder a day at most (D76). healthchecks.io watches the nightly backup, the weekly restore test and the reconciler heartbeat, and notifies Pushover itself.

## Tests

1. **Instance repo CI** on every PR (D48): schema, Butane, `caddy validate`, secrets encrypted and well-formed without decrypting (D35).
2. **Monorepo CI**: unit tests, and end-to-end tests of the reconciler on a miniature platform (D59).
3. **On the server**: a health check per app.
4. **Restore**: weekly on the server (D75); `bivy rebuild --test` every 3 months, with the app check of runbook section 13 (D39, D81).
5. **Apps**: Vitest and Playwright in Playwright's image (D87), checked on the Mac with `dev:local` (D83).

## Environments

No permanent dev or staging (D43): apps on the Mac (`npm run dev:local`), the platform on the miniature platform (`npm run platform:up`), a trial on the real server as an `<app>-preview` manifest, platform changes through CI and `bivy rebuild --test`.
